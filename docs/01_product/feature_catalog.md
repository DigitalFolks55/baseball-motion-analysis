# Feature Catalog

## Repository Foundation

Status: Foundation scaffold only.

The project is being reshaped into a local-PC baseball motion analysis application. Current behavior is limited to a health endpoint and package scaffolding. Local upload/import, local storage, replay, video loading, image-sequence loading, pose estimation, motion evaluation, scoring, and feedback generation are intentionally not implemented yet.

## Local Media Upload and Import

Status: Foundation implemented for local input services and video-only browser upload.

The UI should allow the user to upload or import:

- A video file.
- An ordered image sequence representing motion over time.

Imported media should be validated before storage. The UI should communicate unsupported formats, missing files, unordered sequences, and size or readability problems clearly.

Current foundation:

- Recorded local video files can be loaded from local paths.
- Multiple local image files can be loaded as an image sequence.
- Input modes are normalized into a common frame sequence model for future pose estimation, replay, and motion analysis.
- A local camera stream interface exists for future real-time analysis, but full real-time analysis is not implemented.
- A browser UI can upload video files through FastAPI multipart upload handling.
- Browser uploads stream to a controlled staging file before application-service import.
- Uploaded videos are validated through existing video input behavior and then stored under configurable local or server-side media storage.

Current limitations:

- No full desktop GUI is implemented.
- Browser upload is video-only; image-sequence browser upload is not implemented.
- No browser WebSocket camera streaming is implemented.
- Camera stream behavior is interface-level foundation only.
- Public deployment security, authentication, authorization, and multi-user behavior are not implemented.

## Local Media Storage

Status: Local video library metadata index implemented for browser-uploaded videos.

Uploaded media should be copied or registered in a configurable local data directory. Storage should keep a metadata index for media type, original display name, duration or frame count, dimensions, import time, motion type when selected, analysis status, and generated report locations.

User videos, image sequences, generated reports, model files, and local metadata containing private details must stay out of git.

Current foundation:

- Local media copy behavior is optional and only runs when explicitly requested by a service caller.
- The media root is configurable.
- Copied files preserve their original extension and use collision-safe names.
- Browser-uploaded videos use generated internal filenames and stable media IDs.
- Browser-uploaded video metadata is stored in SQLite.
- API responses expose media IDs and public metadata, not absolute filesystem paths or stored relative paths.
- Browser-uploaded videos can be removed from the media library, which deletes the stored file when present and removes the metadata record.

Current limitations:

- No long-term replay library or generated report persistence is implemented.
- SQLite is suitable for the local MVP, but concurrent server writes need future review before multi-user hosting.

## Replay

Status: Video replay MVP implemented for browser-uploaded videos.

The UI should replay both newly uploaded and previously stored media:

- Video replay should use validated local video files.
- Image-sequence replay should present ordered frames at a configured or detected frame rate.
- Replay metadata should be generated by application services so the UI does not inspect local storage details directly.

Current foundation:

- Stored browser-uploaded videos appear in a media library.
- Replay manifests provide media-ID-based content URLs.
- Video content is served through an API endpoint with byte-range support for browser seeking.
- Stored browser-uploaded videos can be deleted from the library through a media-ID-based API endpoint.
- Playback speed controls support 0.25x, 0.5x, 1x, 1.5x, and 2x.
- Approximate previous-frame and next-frame controls seek by `1 / fps` when FPS is available.

Current limitations:

- MP4 and WebM are the most reliable direct browser replay formats.
- MOV, AVI, and MKV may validate but may not replay in every browser because codec support varies.
- No automatic transcoding or FFmpeg integration is implemented.
- Image-sequence browser replay remains planned.

## Motion Analysis and Feedback

Status: Planned.

The analysis workflow should run locally:

```text
stored media -> frame sampling -> pose estimation -> motion analysis -> scoring -> feedback report
```

Supported motion categories are swing, fielding, throwing, and pitching. Reports should include summary, good points, improvement points, suggested drills or next actions, confidence, and limitations.
